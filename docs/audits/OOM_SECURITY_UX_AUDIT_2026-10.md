## 1. 개요

오픽온미(OOM)는 브라우저 중심의 정적 웹앱으로, 사용자의 음성 녹음 데이터와 AI 피드백을 위한 외부 API 키를 취급합니다.
본 감사는 사용자의 소중한 개인정보(음성 녹음본, 전사 텍스트, 개인 API 키)의 저장 라이프사이클과 네트워크 전송 경로를 정밀 분석하고, 브라우저 환경에서 발생할 수 있는 보안 위협과 UI/UX 접근성을 객관적으로 평가했습니다.

## 2. API 키 및 브라우저 저장소 보안 (BYOK 모델)

### 2.1 저장소 스코프 및 라이프사이클 (`src/lib/customSettingsStorage.ts`)
- **기본 격리 방식**:
  - 사용자가 AI 설정(`/ai-settings/`)에서 OpenAI 또는 호환 API Key를 입력할 때, 기본 상태에서는 **`sessionStorage`**(`oom-llm-settings:key`, `oom-stt-settings:key`)에만 저장됩니다.
  - 사용자가 브라우저 탭을 닫으면 세션 스토리지의 키는 즉시 휘발됩니다. 이는 공용 PC나 도서관 환경에서 브라우저를 종료했을 때 다음 사용자가 디스크 스토리지에서 키를 복원하지 못하도록 방어하는 실용적인 완화(Mitigation) 조치입니다.
- **영구 저장 옵션의 실체**:
  - 사용자가 명시적으로 `이 기기에 API Key 저장 (공유 PC 주의)` 체크박스를 활성화하고 저장한 경우에만 `localStorage`에 보관됩니다.
  - **중요 사실 (보안 유의점)**: `localStorage`에 저장될 때 별도의 클라이언트 암호화 알고리즘이 적용되지 않고 **평문(Plaintext) JSON**으로 저장됩니다. 프런트엔드 단독 환경에서는 복호화 키 역시 클라이언트에 존재할 수밖에 없으므로 진정한 의미의 암호화라 볼 수 없습니다.
  - 따라서 타인과 공유하는 기기나 공용 PC에서는 이 옵션을 **절대로 체크하지 말아야 함**을 사용자 안내에 명확히 명시하고 있습니다.
- **초기화 및 삭제**:
  - "사용자 API 설정 해제" 및 "설정 초기화" 클릭 시 `sessionStorage`와 `localStorage` 모두에서 키와 설정이 즉시 삭제됩니다.

### 2.2 XSS (교차 사이트 스크립팅) 위협 모델 한계
- **정직한 보안 평가**:
  - `sessionStorage`를 사용하는 것은 디스크 영구 잔류 위험을 줄이지만, **XSS 공격에 대한 '원천 차단'이나 '위험 0%'를 의미하지 않습니다.**
  - 만약 사이트 내에 XSS 취약점이 발생하여 악성 자바스크립트가 실행될 경우, 공격 스크립트는 동일 출처의 `sessionStorage`, `localStorage`, 런타임 변수 메모리 어디든 접근하여 API 키를 탈취할 수 있습니다.
  - OOM은 React의 자동 HTML 이스케이프, 위험한 `dangerouslySetInnerHTML`의 엄격한 제한을 통해 XSS를 1차 방어하고 있으나, 사용자에게는 공용 기기 사용 후 반드시 설정을 초기화할 것을 권고합니다.

### 2.3 네트워크 요청 및 에러 노출 방지 (`src/lib/llm.ts`, `src/lib/stt.ts`)
- **요청 헤더 처리**:
  - `Authorization: Bearer <API_KEY>` 또는 `x-api-key: <API_KEY>` 헤더를 사용하여 엔드포인트로 전송됩니다.
- **로그 및 에러 메시지 보호**:
  - 소스코드 전수 검사 결과, API Key나 Authorization 헤더 값을 `console.log`로 출력하는 구문이 없습니다.
  - 네트워크 장애나 HTTP 에러 발생 시에도 `LLM 요청이 401로 실패했습니다`와 같이 상태 코드만 사용자에게 노출하며, 에러 본문에 키가 포함되어 반환되지 않도록 처리되어 있습니다.
- **응답 페이로드 제한**:
  - LLM 응답 텍스트 길이가 30,000자를 초과하면 즉시 거절(`raw.length > 30000`)하여 브라우저 메모리 고갈을 방지합니다.

## 3. 음성 녹음 및 AI 데이터 전송 경로 점검

### 3.1 마이크 권한 및 캡처 (`src/components/practice/Recorder.tsx`)
- **권한 요청 시점**:
  - 페이지 진입 시점에 무단으로 권한을 요구하지 않으며, 사용자가 "Record" 버튼을 명시적으로 클릭했을 때만 브라우저 권한 팝업이 호출됩니다.
- **권한 거부 시 동작**:
  - 마이크 권한이 거부되면 타이머가 시작되지 않고, "마이크 사용 권한이 필요합니다" 안내와 함께 타이머만 작동시키는 무음 연습 모드로 안전하게 전환할 수 있습니다.

### 3.2 음성 데이터의 라이프사이클 및 외부 전송 경로
- **브라우저 로컬 격리**:
  - 녹음된 오디오는 브라우저 메모리의 일시적 `Blob` 객체(`audio/webm` 등)로만 보관되며, `localStorage`에 Base64로 저장되지 않습니다.
  - 문제가 바뀌거나 재시도 시 이전 Blob URL이 해제(`URL.revokeObjectURL`)되어 메모리가 정리됩니다.
- **OOM 자체 서버 미전송**:
  - OOM 자체 웹서버나 백엔드로는 사용자의 음성 파일이 절대 업로드되지 않습니다.
- **외부 API 전송 경로 (정확한 사실 명시)**:
  1. **커스텀 STT 사용 시**: 사용자가 AI 설정에서 Whisper 등 커스텀 STT URL을 등록한 경우, 녹음된 오디오 `Blob` 파일이 브라우저에서 **해당 사용자가 입력한 외부 STT 서버로 직접 전송**됩니다.
  2. **AI 피드백 요청 시**: 음성 파일 원본은 전송되지 않으며, STT를 통해 변환된 **텍스트 전사본(transcript)**과 질문 프롬프트만 외부 LLM(또는 관리형 AI 사용 시 Google Gemini)으로 전송됩니다.

## 4. UI/UX 및 웹 접근성 (A11y) 점검 현황

### 4.1 데스크톱 사이드바 (LNB)
- **레이아웃 구조**:
  - 기본 240px(`w-60`) ↔ 축소 모드 68px(`w-[68px]`).
  - 상단 로고와 하단 유틸리티는 뷰포트에 고정되며, 중앙의 네비게이션 메뉴 영역만 독립 스크롤(`overflow-y-auto`)되어 언제나 최적의 조작성을 유지합니다.
  - 1024~1279px 구간에서의 2열 겹침 현상을 `xl`(1280px 이상)로 전환 기준을 높여 해소했습니다.

### 4.2 모바일 서랍 네비게이션 (Drawer)
- **접근성 속성 적용**:
  - `role="dialog"`, `aria-modal="true"` 적용.
  - 키보드 `Escape` 입력 시 서랍 닫기 및 포커스 복원 지원.
  - 터치 타겟은 최소 44px 이상을 유지하도록 CSS가 구성되어 있습니다.

### 4.3 색상 대비 및 다크 모드
- **명도 대비**: WCAG AA 기준(4.5:1 이상)을 충족하는 Zinc/Slate 중립 배경 및 Indigo 악센트 적용.
- **테마 보존**: `localStorage('oom-theme')`에 사용자 선호(light/dark)를 저장하여 재방문 시 유지.

### 4.4 접근성 및 E2E 검증 범위 한계 (수동 확인 필요 사항)
- **단위/컴포넌트 테스트 완료**: Testing Library 기반의 포커스 이동, ARIA 속성, 버튼 비활성화 상태는 자동화 테스트로 확인되었습니다.
- **실기기 미검증**: 실제 시각장애인용 스크린리더(NVDA, VoiceOver) 음성 출력 품질 및 다양한 저사양 안드로이드/iOS 실기기에서의 터치 반응은 에뮬레이션 테스트 범위를 넘어서므로, 운영자의 지속적인 실기기 수동 모니터링이 권장됩니다.
